# SSH KRL Client Distribution Milestone

> Human-readable anchor for the **SSH KRL Client Distribution** milestone (15 tasks, TASK-159..173, KRLC-01..KRLC-14 + the KRLC-02a gate spike).
> Extends: [TASK-145 (SSH-24)](../tasks/task-145%20-%20SSH-24-Stateless-encrypted-KRL-distribution-sidecar-host-side-puller.md) — the host-side puller sketch.
> Decisions: [decision-013 — SSH KRL Distribution](../decisions/decision-013%20-%20SSH-KRL-Distribution.md) ·
> decision-015 — SSH KRL Client Decryption Model *(authored by KRLC-14)*.

## Goal

Turn the SSH-24 host-side-puller sketch (TASK-145) and the user's bash prototype into a
production-grade, single **static linux/amd64 Go binary** (`krl-client`) that keeps each host's
`/etc/ssh/revoked_keys` (OpenSSH `RevokedKeys` / KRL) current from crontab or a systemd timer. Each
run POSTs the encrypted per-host endpoint `POST /api/v1/external/ssh/krl {host_id}` with
`If-None-Match` caching (304 → no-op), **decrypts the ECIES payload locally with a host-held private
key**, validates `host_id` / `valid_until` / version-monotonicity, verifies the detached CA
signature over the bare KRL, then **atomically installs it `0444 root:root`** — more precise and
professional than the prototype, with proper flags/config/env, exit codes, structured logging, a
complete test suite, supply-chain CI, and operator docs. The binary is CI/CD-built and published as a
versioned artifact on the GitHub Release for each pki-manager `cz bump` `vX.Y.Z` tag.

## Decision: local-key decryption, reusing the existing SSH host key

The shipped model is **local-key** (chosen over KMS-resident): the host decrypts the payload entirely
in-process — **no per-host KMS access**, no `cosmian` CLI — and it does so by **reusing the host's
existing SSH host keypair** (`/etc/ssh/ssh_host_ecdsa_key`, an ECDSA nistp256 key) as the ECIES key,
exactly as the user's prototype did. No separate key is generated by default, and because pki-manager
already stores the host's public key (`ssh_hosts.opensshHostPubkey`), **no new key registration is
needed** for hosts that registered with an ecdsa key.

This is a **rebuild, not an add-on** (KRLC-02, blocking): decryption **must never** touch the KMS.
Today `registerHostEciesKey` generates the ECIES keypair *inside* the Cosmian KMS and `POST /krl`
encrypts to that KMS-resident pubkey, with the host decrypting **via the KMS** — that is exactly the
behaviour being removed. KRLC-02 replaces it with a **native backend** implementation (`node:crypto`)
that encrypts to the host's **already-registered public key** (`ssh_hosts.opensshHostPubkey`), pins a
**standard, cross-impl ECIES envelope** (P-256 + HKDF-SHA256 + AES-256-GCM, framing
`ephemeral-pubkey || nonce || ciphertext || tag`), and **retires** the KMS
`CreateKeyPair`/`Encrypt`/`Decrypt` path plus `ssh_hosts.kms_pubkey_id` (migrating existing hosts).
This **supersedes** decision-013's KMS-resident *adopted model* and the KMS-decrypt parts of SSH-15
(TASK-133) / SSH-24 (TASK-145); recorded in **decision-015** (KRLC-14). **Constraint:** ECIES needs
P-256, so the host must have an ecdsa host key; an ed25519-cert host registers its
`/etc/ssh/ssh_host_ecdsa_key.pub`. A dedicated ECIES key stays available via `--host-key` (trade-off
documented).

## Three corrections over the prototype (load-bearing)

1. **`If-None-Match` is the server's `krl_version`** (`sha256:<hex>` echoed from the `X-KRL-Version`
   response header), **not** a sha256 of the local `revoked_keys` file — the backend compares against
   its stored `versionHash`, so the prototype's file-hash would never match and would force a full
   re-decrypt on every poll.
2. **The CA signature is DER ECDSA-P256 over SHA-256 of the bare KRL**, verified with
   `ecdsa.VerifyASN1` after converting the OpenSSH `ca.pub` via `ssh.ParseAuthorizedKey` →
   `CryptoPublicKey` — **no `openssl` dependency** (`openssl dgst -verify` can't parse
   `ecdsa-sha2-nistp256 AAAA…` directly).
3. **Anti-rollback**: reject any `krl_version` / `krl_number` not strictly newer than the installed
   one (persisted in `--state-dir`), preventing replay/downgrade of an older revocation set.

## Placement & layout

New top-level Go module **`krl-client/`** (module `github.com/oriolrius/pki-manager-krl-client`,
`go 1.26`, latest), a peer to `k8s/issuer/` — it is a **host agent**, not a Kubernetes controller. Flat
layout mirroring the issuer convention: `main.go` at root (no `cmd/`), logic under
`internal/{config,krlclient,decrypt,payload,verify,installer,state,logx,app}`, plus
`Makefile` / `README.md` / `packaging/` (systemd unit+timer, crontab). Self-contained: std-lib
crypto/HTTP + `golang.org/x/crypto/ssh` + `gopkg.in/yaml.v3`; **no `cosmian`/`jq`/`openssl`/`curl`
shell-outs.**

## Canonical on-host paths (single source of truth)

All client on-host defaults are **derived from** `backend/src/services/ssh-config.ts` — the declared
"SINGLE SOURCE OF TRUTH for every on-host path" — so the client, the generated `60-ssh-ca.conf`
drop-in, and the Ansible role can never disagree. A host provisioned from that drop-in needs only
`--server-url`.

| Flag | Default | `ssh-config.ts` constant |
|---|---|---|
| `--host-key` (ECIES = SSH host key) | `/etc/ssh/ssh_host_ecdsa_key` | `hostKeyPathFor('ecdsa-sha2-nistp256')` |
| `--ca-pubkey` (KRL-sig trust) | `/etc/ssh/ssh-user-ca.pub` | `USER_CA_PATH` (`TrustedUserCAKeys`) |
| `--krl-file` (install target) | `/etc/ssh/revoked_keys` | `REVOKED_KEYS_PATH` (`RevokedKeys`) |
| `--host-id` | `hostname -f` | host FQDN |

Client-owned paths (not pki-manager artifacts) keep their own defaults: `--state-dir`
`/var/lib/krl-client`, `--config` `/etc/krl-client/config.yaml`.

## Runtime flow

| # | Step |
|---|---|
| 1 | Load config (flags > env `KRL_CLIENT_*` > `/etc/krl-client/config.yaml` > defaults); default `--host-id` = `hostname -f`; read cached `krl_version`/`krl_number` from `--state-dir`. |
| 2 | `POST {server-url}/api/v1/external/ssh/krl`, body `{"host_id":"<fqdn>"}`, header `If-None-Match: <cached krl_version>`; TLS verified (`--ca-bundle`), `--timeout`, `--retries` on transport/5xx. |
| 3 | **304** → up-to-date, exit 0 (no write). Error codes → mapped exits (see table). **200** → read body (ECIES ciphertext) + `X-KRL-Version`. |
| 4 | **Decrypt locally** with the host's SSH key (`--host-key`, default `/etc/ssh/ssh_host_ecdsa_key`): ECDH(host key, ephemeral pubkey) → HKDF-SHA256 → AES-256-GCM open → plaintext JSON. Failure → exit 3. |
| 5 | Parse `{krl, ca_signature, krl_version, valid_until, host_id}`; validate host_id / valid_until / `sha256(krl)==krl_version==X-KRL-Version` / monotonic (exits 6/5/8). |
| 6 | Verify detached CA signature (`ecdsa.VerifyASN1`, DER over `sha256(krl)`); `null` sig installs only under `--allow-unsigned`; bad sig → exit 4. |
| 7 | **Atomic install** (skip on `--dry-run`): temp file (0600) → fsync → chmod 0444 → chown 0:0 → `os.Rename` → dir fsync. Failure → exit 7. |
| 8 | Persist new version/state atomically; emit one structured log event; exit 0. Operator reloads sshd out-of-band (`sshd -t && systemctl reload ssh`). |

## Exit codes

`0` up-to-date/updated · `1` config/usage · `2` network/transport (incl. 5xx/503/500) · `3` decrypt ·
`4` CA-signature verify · `5` expired (`valid_until`) · `6` host-id mismatch · `7` install ·
`8` version/integrity/anti-rollback · `9` not provisioned / feature disabled (400/404/501) ·
`10` rate-limited (429).

## Top risks & mitigations

- **ECIES interop** — a native Go decryptor must byte-match the backend's envelope. → KRLC-02 pins a
  standard, documented scheme (P-256/HKDF-SHA256/AES-256-GCM) with encrypt→decrypt vectors, rather
  than reversing Cosmian's opaque ECIES.
- **Prototype `If-None-Match` is wrong** (never matches `versionHash`). → KRLC-03/07 persist and echo
  the verbatim `X-KRL-Version` token; KRLC-11 asserts a 304 on the second poll.
- **OpenSSH `ca.pub` is not openssl-parseable.** → KRLC-06 converts via `ssh.ParseAuthorizedKey` and
  verifies the DER signature with `ecdsa.VerifyASN1`.
- **CA-selection asymmetry** — the encrypted `/krl` currently resolves the **Host CA** KRL, while
  sshd `RevokedKeys` semantically wants the **User CA** KRL (the plaintext `/krl/<userCaId>.bin` cron
  targets the User CA). → KRLC-13/KRLC-14 document the caveat and decision-015 records it; the client
  is not presented as a drop-in for the User-CA bundle cron until reconciled *(open, backend)*.
- **ssh-mon staleness on 304-only clients** — telemetry (`last_krl_fetch_at`) refreshes only on 200.
  → KRLC-13 documents a poll interval inside the ~30m (2× interval) window; a periodic unconditional
  fetch or a backend telemetry-on-304 change is an open question.
- **Clock drift** breaks `valid_until` and short user-cert TTLs. → KRLC-05 applies `--clock-skew`;
  README pins NTP as a hard prerequisite.
- **P-256 requirement** — ECIES needs an ecdsa nistp256 key; ed25519-only hosts can't decrypt with
  their cert key. → default `--host-key` is `/etc/ssh/ssh_host_ecdsa_key` (sshd generates one by
  default); ed25519-cert hosts register their ecdsa host pubkey (KRLC-02/KRLC-10). Reusing the SSH
  host key for ECIES is a documented trade-off, with a dedicated-key override via `--host-key`.
- **Rebuild migrates shipped state** — SSH-15/SSH-24 shipped the KMS-resident model (Done); KRLC-02
  retires it and must migrate existing hosts (`kms_pubkey_id` → native encrypt-to-`opensshHostPubkey`)
  and mark decision-013 superseded. Highest-risk item: prove the native envelope round-trips
  backend→Go-client BEFORE committing (KRLC-02 vector-test AC; optionally a standalone spike like
  decision-013's TASK-144). → decision-015 records the supersession.
- **Null CA signature** (server graceful-degradation). → KRLC-06 fails closed unless
  `--allow-unsigned`; never a silent pass.

## Open questions (deferred / backend)

- **CA-selection reconciliation**: fix the encrypted `/krl` to serve the **User CA** KRL to match
  sshd `RevokedKeys` semantics, or accept Host-CA behavior and only document it? *(recorded in decision-015)*
- **Telemetry on 304**: force periodic unconditional 200s client-side, or bump
  `ssh_hosts.last_krl_fetch_at` on 304 server-side, to keep well-behaved conditional clients out of
  ssh-mon's stale bucket?
